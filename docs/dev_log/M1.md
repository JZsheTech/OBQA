## M1 Execution Plan — Database Initialization & Repository Layer

**Reference Docs**
- `docs/en/Develop_Road_Map.md` (Milestone scope & DoD)
- `docs/en/Data_Model.md` (table definitions, FK/index requirements)
- `docs/en/backend_frontend_interactive_design.md` (response envelope for `/collections`)
- `dependency/oceanBaseDemo/ob_sqlAlchemy_demo.py` & `ob_vector_utils.py` (connection + vector column patterns)

1. **Author the OceanBase schema DDL**
   - File to add: `EviQAsys/backend/app/repositories/sql/schema.sql`.
   - Content: `CREATE TABLE` statements for `collections`, `documents`, `elements`, `chats`, `turns`, `turn2evidence` plus required indexes from the roadmap (`idx_chat_turn`, `idx_turn_element`). Define sensible types per `Data_Model.md`, include `DEFAULT CURRENT_TIMESTAMP` where appropriate, and parameterise `vec_embedding` dimension via `VECTOR({dimension})` placeholder comment.
   - Also add `USE`/`CREATE DATABASE IF NOT EXISTS` guard comments so the script can run against a target schema configured by environment variables.

2. **Provide a reusable DB connection helper**
   - File to add: `EviQAsys/backend/app/repositories/db.py`.
   - Content: `sqlAlchemy`-based connection factory using env vars (`OB_HOST`, `OB_PORT`, `OB_USER`, `OB_PASSWORD`, `OB_DATABASE`, `OB_TIMEOUT`). Expose `get_connection()` contextmanager and `execute_script(path)` utility that runs the schema SQL file with explicit autocommit + transaction handling, mirroring the OceanBase demo patterns.
   - Export configuration defaults (e.g., `DEFAULT_CHARSET`, `VECTOR_DIM`) for repositories to reuse.

3. **Create a lightweight repository base utility**
   - File to add: `EviQAsys/backend/app/repositories/base.py`.
   - Content: shared helpers for building SQL statements (e.g., `dict_to_insert`), a thin `RepositoryResult` dataclass, and wrappers to map cursor rows to dictionaries; centralises error handling/logging so concrete repositories stay focused on SQL text.

4. **Implement table-specific repositories (non-ORM gateways)**
   - Files to add under `EviQAsys/backend/app/repositories/`: `collections_repo.py`, `documents_repo.py`, `elements_repo.py`, `chats_repo.py`, `turns_repo.py`, `turn2evidence_repo.py`.
   - Content per file: repository class with CRUD methods matching roadmap needs (`create_*`, `get_by_id`, `list_by_foreign_key`, `update`, `delete`). Each method composes pure SQL strings, uses the base helpers, and enforces FK relationships (e.g., `documents_repo.list_by_collection(collection_id: int)`).
   - Include TODO placeholders for future vector search logic in `elements_repo` (in line with M3) and ensure `turn2evidence` repository exposes bulk insert helper for anchor binding.

5. **Expose repositories via package init**
   - Update file: `EviQAsys/backend/app/repositories/__init__.py`.
   - Content: import and re-export repository classes plus constants so service layers can do `from ....repositories import CollectionsRepository`.

6. **Define API-facing schemas**
   - Files to add under `EviQAsys/backend/app/schemas/`: `collection.py`, `document.py`, `chat.py`.
   - Content: Pydantic models (`CollectionBase`, `CollectionCreate`, `CollectionRead`, etc.) reflecting DB columns and typed to align with docs. Provide `Config` to allow orm_mode-like behaviour for dict rows.
   - Update `EviQAsys/backend/app/schemas/__init__.py` to export these models.

7. **Wire repositories into FastAPI endpoints**
   - File to add: `EviQAsys/backend/app/api/routes/collections.py`.
   - Content: APIRouter with `GET /collections` (returns empty list initially via repository), `POST /collections`, `DELETE /collections/{id}` stubs ready for later milestones. Ensure responses follow the unified envelope from interactive design doc (`{"code": "OK", "data": ...}`).
   - Update (or create) `EviQAsys/backend/app/api/__init__.py` to expose `api_router`, and add `EviQAsys/backend/app/main.py` to instantiate `FastAPI`, include router, and register startup event that runs the schema initializer if `RUN_SCHEMA_MIGRATION` env flag is set.

8. **Add repository unit tests**
   - Files to add under `EviQAsys/backend/tests/repositories/`: e.g., `test_collections_repo.py`, `test_documents_repo.py`.
   - Content: pytest fixtures bootstrapping a temporary OceanBase schema (or sqlAlchemy connection to test DB); tests cover happy-path CRUD plus FK constraint failures, aligning with DoD requirement “CRUD testable.”
   - Include a `tests/conftest.py` fixture that runs the schema SQL once per session using the helper from Step 2.

9. **Manual verification checklist**
   - Document in `docs/dev_log/M1.md` (this file) once implementation is done: run schema initializer, execute unit tests, start FastAPI (`uvicorn ...`) and confirm `GET /collections` → `[]`, matching roadmap DoD.
