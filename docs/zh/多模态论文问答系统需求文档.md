
# 背景描述

当前大多数通用网页AI工具在根据一篇或多篇pdf论文回答用户问题时会通读全文然后直接给出答案，然而由于LLM固有的幻觉问题，回答可能会出现一些偏差，而这些网页AI模型并没有展示它们的回答所参考的原论文中的Evidence是什么，这让用户难以判断它们的回答是否遵循了原文，从而影响了AI辅助论文阅读的可靠性。

# 需求分析

我们希望设计一个能显示 Evidence 的论文问答 Agent 系统的 demo，依靠几个简单的 Agent，让 AI 在根据内容回答用户 question 的同时输出相应的 Evidence，这些 Evidence 是原文中的一些元素（chunk），比如文本段落、图片、表格等，这些元素要在前端能够高亮地展示出来。

问答方面只要能实现下面的功能即可：

单轮问答 ：{多篇论文 + 1跳问题 + 1次检索 -> 答案 + evidence_element}
多轮问答 ： 多个单轮问答，记忆用简单的前几轮单轮问答的结果拼接，设置长度限制，超过限制截断。

前端功能：
- 用户创建Collection
- 用户向Collection中上传多篇文档
- 用户针对Collection中的多篇文档进行提问
- 用户提问的历史记录。

为了简化和教学的目的，我们进行下面的简化处理：
- 直接用 MinerU 解析出的元素建索引（仅进行简单的标题层级筛选），不进行重新拆分和合并。
- 使用 DSPy（包名 `dspy`）仅编排文本流程：问句重写、文本回答生成与锚点输出。DSPy 内的签名不携带图像，仅接受 `element_id/elem_type/text_content`。
- 默认回答仅基于文本上下文：image/table 等元素仅以其 `text_caption` 参与检索与回答。
- 可选“图像理解”路径：对检索命中的 image 元素，依据用户 `question` 与检索 `query` 派生 1 个图片子问题，通过独立的视觉问答接口（OpenAI 兼容）在后端完成一次图文问答，产出文字摘要；把该摘要与 `text_caption` 合并为文本上下文再交由 DSPy 的文本回答模块使用。
- 每个 chat 直接使用最近几轮 turn 作为 memory，超过长度就进行简单的 summary。
