# 宏观交互逻辑设计（已合并）

本文件内容已合并入主设计文档：`docs/zh/多模态论文问答系统设计文档.md`。

- 接口路径统一为以 `/api` 为前缀（`/healthz` 例外）。
- 响应 envelope 统一为成功 `{"code":"OK","data":...}`，错误 `{"code":"SOME_ERROR","message":"..."}`。
- 交互流程采用同步设计，已移除后台异步与轮询说明。

M4 更新要点（锚点与 Evidence 编号）：
- 服务与 LLM 内部统一使用 `[Elem#<element_id>]` 锚点；
- 后端在 API 返回前按“元素在 chat 中首次出现顺序”动态生成 `element_id → evidence_no` 映射，在响应体中附带 `evidences` 数组；`answer_text` 字段本身保留 `[Elem#id]`，由前端在渲染阶段将其显示为 `[Evidence#no]`（详见《Evidence 渲染规范》）。
- 桥表改为 `turn2element`，仅存 `(chat_id, turn_id, element_id)`；`evidence_no` 不再入库，且仅为答案文本中真实出现的 `[Elem#id]` 写入记录。

请以主设计文档为准，后续更新不再在本文件重复维护。
