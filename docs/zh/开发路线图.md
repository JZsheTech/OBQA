## 串行阶段划分（6 个里程碑）

> 每个阶段均给出**完成判定（DoD）**与**主任务清单（按实现顺序）**。按此顺序逐项完成即可。

### M0. 开发环境与空仓库骨架（目标：能启动空 API）

**DoD：** 本机/服务器上，`uvicorn` 能启动 FastAPI；前端能以最简页面发起 GET 健康检查。
**主任务：**

6. 建立 2 个 Conda 环境：`quest`（FastAPI、DsPy）与 `jzMinerUVllm`（MinerU 本地服务）；启动 OceanBase Docker（最小单节点）。
7. 组织仓库目录（建议）：`backend/`、`frontend/`、`dependency/`（直接指向现有样例）。
8. 后端创建最小路由组：`GET /healthz -> {ok:true}`。
9. 前端用最薄的 fetch 封装连通健康检查（无需状态管理框架）。

---

### M1. 数据库初始化与仓储层（目标：表可用、CRUD 可测）

**DoD：** OceanBase 中六张表建成，后端可通过仓储函数完成基本 CRUD，`GET /collections` 能返回空列表。
**主任务：**

10. 依据统一数据模型编写 DDL：

   * 表：`collections / documents / elements / chats / turns / turn2evidence`；
   * 关键外键与索引：`documents.collection_id`、`elements.doc_id`、`turn2evidence (turn_id,evidence_no) PK`、`idx_chat_turn`、`idx_turn_element`。
11. 实现**无 ORM**的表网关（仓储层）：`collections_repo.py / documents_repo.py / elements_repo.py / chats_repo.py / turns_repo.py / t2e_repo.py`。
12. 用 `dependency/oceanBaseDemo` 的连接示例打通连接与事务处理。

---

### M2. 文档上传→MinerU 解析→入库（目标：首个 PDF 成功落表为元素）

**DoD：** 前端上传一个 PDF，后端同步串行：调用 MinerU→获得 `content_list + md_text`→标准化→写入 `documents/elements`，前端能在“文档列表”看到该 PDF。
**主任务：**

13. 后端 `POST /collections/{id}/documents`（multipart）：控制服务接收文件、保存元信息、**阻塞式**调用 MinerU 接口，拿到 `content_list / md_text`。
14. 执行“标题层级修复 + 统一元素化”：为每个元素写入 `header_name / level_nav / page_no / bbox / text_caption` 等字段；Header 节点生成简要 section 摘要文本；遵循“**元素是最小索引单元**”的统一结构。
15. 以**统一文本视图**存入：

   * 纯文本：`header_name + level_nav + text_content`；
   * header：`header_name + level_nav + section_summary`；
   * 图/表：使用 caption 形成 `text_content`，图像 base64 存 `image_base64`。
16. 采用 `dependency/minerUparseDemo/parse_pdf_minerU.py` 作为对接样例起点。

> 备注：与“前端轮询状态”不同，本 Demo 采用**同步入库**以保证单人串行的可控性；此做法与“服务同步、可预测副作用”的蓝图一致。

---

### M3. 向量化与检索（目标：能检向量返回候选元素）

**DoD：** 通过后端脚本或 API 触发对刚入库元素的向量化，完成 `elements.vec_embedding` 写入；`/retrieval/test` 能依据查询返回若干候选元素（含类型与元数据）。
**主任务：**

17. 文本类元素（text/table/equation）：仅对 `text_content` 生成向量；图像类元素（image）：对 `image_base64` 生成向量；采用 Qwen 系列/多模态嵌入模型，先跑通 `dependency/multiModalEmbedding` 的 Demo，再封装到 `embedding_service.py`。
18. 在仓储层增加**简单的向量近邻查找**（可先用余弦相似度 + TopK，后续再优化），检索时附带 `doc_id / page_no / bbox / elem_type`。
19. 预留“去重与类型分桶”接口（但先不复杂化）。

---

### M4. 问答主干（DsPy 编排、证据锚点绑定）（目标：能问出带 `[Evidence#no]` 的答案）

**DoD：** 在某 Collection 下创建 Chat，向后端 `POST /chats/{chat_id}/turns` 发送问题，返回：`answer` 文本内含 `[Evidence#1]...[Evidence#n]`，并且 `turn2evidence` 表已写入映射，`GET /turns/{turn_id}/evidences` 能取到每个证据的 `doc_id/page_no/bbox/snippet`。
**主任务：**

20. **问句重写**：使用 DsPy/LLM 先做轻量重写以利检索。
21. **检索**：用重写后的 query 进行向量召回，按类型分组与粗过滤，得到候选证据元素。
22. **记忆**：仅拼接最近若干轮（例如 3 轮），超限则生成简要摘要文本参与提示词。
23. **答案生成**：构造多模态提示（文本拼接 + 图像列表）并**显式要求模型在生成中输出锚点**（`[Evidence#no]`）；完成后把 `turn_id, evidence_no -> element_id` 写入桥表，确保锚点可追溯。
24. 使用 `dependency/DspyDemo` 作为 LLM/编排接入的脚手架。

---

### M5. 最小前端（集合/上传/聊天/高亮跳转）（目标：端到端 Demo 可演示）

**DoD：** 前端具备 4 个最小页面/视图：集合页、文档页（含上传）、聊天页（问答记录列表）、PDF 预览与证据高亮跳转；点击答案中的 `[Evidence#no]` 能定位原文区域高亮。
**主任务：**

25. **接口对齐**：实现并接线以下最小 API（与交互设计一致）：

   * `GET /collections`, `POST /collections`, `DELETE /collections/{id}`；
   * `POST /collections/{id}/documents`, `GET /documents/{doc_id}/file`；
   * `POST /collections/{id}/chats`, `GET /chats/{chat_id}`；
   * `POST /chats/{chat_id}/turns`, `GET /turns/{turn_id}/evidences`。
26. **锚点解析与跳转**：聊天区把 `[Evidence#no]` 渲染为可点击链接；点击后调用 evidences 接口，驱动 PDF Viewer 跳转到 `page_no` 并用 `bbox` 高亮。
27. 界面保持“薄层”实现：纯 React + `fetch` 包装，无全局状态库；API 返回使用统一 envelope。

---


## 建议的实现顺序（codex 智能体的任务清单）

28. **M0**：初始化 Conda 环境与空 FastAPI；`GET /healthz`。
29. **M1**：执行 DDL 建表；完成 `collections_repo` 与 `documents_repo`，跑通 `GET /collections`。
30. **M2**：接入 MinerU 解析接口，完成 `POST /collections/{id}/documents` 同步入库；前端做最小上传表单。
31. **M3**：封装 `embedding_service`，对已入库元素批量向量化；实现 `/retrieval/test`。
32. **M4**：串联 DsPy：问句重写→检索→答案生成（含锚点）；写入 `turns` 与 `turn2evidence`。
33. **M5**：完成聊天页与 PDF 高亮跳转；统一响应 envelope；做 1 套端到端演示脚本。

---

## M6 验收脚本（端到端自测）

* **创建集合** → `POST /collections {name:"Demo"}` 返回 `id`；**上传 PDF** → 返回 `doc_id`；**向量化** → 触发一次批处理；**新建聊天** → `POST /collections/{id}/chats`；**提问** → `POST /chats/{chat_id}/turns`，响应文本含 `[Evidence#1]`；**点击锚点** → 前端请求 `GET /turns/{turn_id}/evidences`，PDF Viewer 定位并高亮。
  以上步骤分别契合**需求**、**数据模型**、**蓝图流程**、**设计与交互**的核心约束。
