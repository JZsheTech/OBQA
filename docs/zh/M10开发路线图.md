
# ✅《多模态问答流程重构指南（v3 最终工程版）》


# 1. 架构一句话描述

> **Text / Image / Memory 的检索全部产出 element，展开 → 去重 → 合并 → 直接输入 AnswerAgent（OpenAI VLM），输出答案与 element_id。**

---

# 2. 四阶段主流程（工程可落地）

## Phase 1：检索层（Text / Image / Memory）

三个 Agent 的职责互不冲突，且 **只有 TextRetrieveAgent 与 MemoryAgent 使用 DSPy**。

### 2.1 TextRetrieveAgent（使用 dspy）

**输入**：question + memory
**功能**：

* query rewrite（dspy）
* 文本向量检索 → TopK text-chunks
  **输出**：`text_chunks`

### 2.2 ImageRetrieveAgent（无 dspy；可选）

**仅在 `use_image = true` 时执行**

**输入**：question + memory
**功能**：图片向量检索（可加 rewrite）
**输出**：`image_chunks`

### 2.3 MemoryAgent（使用 dspy）

内部分为两部分：

#### （A）记忆更新（memory_generation，用于 turn 写入）

输入：`last_turn_memory` + 当前 turn 的 Q/A
输出：`new_memory`
逻辑如下：

1. 尝试：`last_memory + 当前 Q/A` 是否超过 memory_max_length
2. 若 **不超过** → 直接拼接
3. 若 **超过** → 调用 LLM（dspy）生成 `memory_summary`

   * 自动剪裁无关 elem_id
   * 保留必要的 elem_id 引用（以 `[Elem#id]` 形式存在）

并写入 turns 表的 `memory` 列。

> ⚠ 记忆入库前，用正则匹配其中的[Elem#id] (跟QA中的answer中的格式一样)，通过数据库检索确定该id是否真实存在，如果不存在，则将记忆中的这些不存在的[Elem#id]去掉(其他文本部分保留)，并在后端给出 warning log。

#### （B）记忆检索（memory_selection，用于生成 evidence）

输入：当前 turn 的 question + 上一个turn 的 memory
输出：

* `memory_text_elements`
* `memory_image_elements`（若 use_image=false → 丢弃）

用LLM从 memory 中抽取对当前question有帮助的 element_id → 验证 → 去掉不存在的 id。

---

## Phase 2：Chunk → Element 展开（统一逻辑）

对所有检索到的 chunk 结构进行「扁平化」：通过内部的elem_ids逐个到elements表中去查。

```
text_chunks  → expand_chunk → text_chunk_elements
image_chunks → expand_chunk → image_chunk_elements
```

MemoryAgent 给出的已经是 element_id，不需要展开。

展开需保留：

* element_id
* element_type（text / image）
* 位置（doc_id, page_id, bbox）
* text_content / image_base64

---

## Phase 3：候选元素拼接（无 rerank）

遵循极简原则：

```
candidate_elements =
    text_chunk_elements
  + image_chunk_elements (if use_image)
  + memory_text_elements
  + memory_image_elements (if use_image)
```

唯一处理：**dedup**（按 element_id 去重）

❌ 不 rerank
❌ 不过滤
❌ 不评分

就是**最简单、最透明的合并**。

---

## Phase 4：AnswerAgent（OpenAI VLM，完全无 dspy）

输入：

* question
* memory_summary（来自 turns.memory）
* candidate_elements（包含 text + image）
* use_image（控制是否将图片送入 VLM）

AnswerAgent 直接调用：

```
client.responses.create(
    model="gpt-4.1",
    input=[question, memory_summary, candidate_elements]
)
```

输出：

* answer_text：包含 `[Elem#123]`
* answer_evidence_ids：模型引用过的 element_id（通过结构化输出或 regex 提取）

---

# 3. Evidence 编号（后端统一生成）

后端维护一个「聊天级别」的 evidence_no 映射：

* 首次出现的 element_id → 分配新的 evidence_no (1,2,3…)
* 后续出现 → 复用之前的 evidence_no
* evidence_no 不落库（chat 结束后丢弃）
* API 返回：

```json
{
  "answer": "...",
  "evidence_map": {
      "Elem#52": 1,
      "Elem#87": 2
  }
}
```

# 4. 记忆维护逻辑（新补充：可直接给 coder）

### （1）turns 表新增字段

| 字段名      | 含义                                      |
| -------- | --------------------------------------- |
| `memory` | 本 turn 的 memory_summary（字符串，包含 elem_id） |

### （2）更新逻辑（Pseudo-code）

```python
def update_memory(last_memory, current_qa):
    concat = last_memory + "\n" + current_qa
    if len(concat) <= MEMORY_MAX_LEN:
        return concat

    # 超长 → 调 LLM 总结
    summary = LLM.summarize(concat)
    summary = clean_invalid_elem_ids(summary)
    return summary
```

### （3）从 memory 中抽取 evidence

```python
elem_ids = extract_elem_ids(memory)
valid_ids = [eid for eid in elem_ids if exists_in_db(eid)]
```

不存在的 elem_id → 丢弃 + warning。

# 5. dspy 使用规范（简明可执行）

| Agent              | 是否使用 DSPy | 内容                       |
| ------------------ | --------- | ------------------------ |
| TextRetrieveAgent  | ✔         | Query rewrite、检索策略优化     |
| MemoryAgent        | ✔         | 记忆 summary、记忆 element 选择 |
| ImageRetrieveAgent | ✘         | 不使用 dspy                 |
| ExpandChunks       | ✘         | 无需 LLM                   |
| AnswerAgent        | ✘         | **直接 OpenAI VLM**        |

**唯一用 dspy 的地方：Retrieve + Memory**
**其他全部走 OpenAI 官方 SDK**。

# 7. 参数控制表（最终清理版）

| 参数                          | 含义                        |
| --------------------------- | ------------------------- |
| `use_image`                 | 控制是否启用图片检索与图片 evidence    |
| `text_retrieve_topk`        | 文本 chunk 检索 top-k         |
| `image_retrieve_topk`       | 图片 chunk 检索 top-k         |
| `memory_element_topk`       | MemoryAgent 初筛 element 上限 |
| `text_memory_element_topk`  | 记忆中的文本 element 上限         |
| `image_memory_element_topk` | 记忆中的图片 element 上限         |

# 删除turn2element表
turn2element表应当删除，在恢复聊天历史时，正则匹配每个turn的answer中的[Elem#id] 然后到数据库中找对应元素的信息即可，不需要额外存一个turn2element表
